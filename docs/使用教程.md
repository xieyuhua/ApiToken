# apitoken 使用教程

> 5 分钟跑通第一个请求：**启动 → 改密钥 → 加渠道 → 调用**。
> 本教程以仓库自带的 `config.yaml` 为准（监听 `:18125`、网关密钥/管理令牌均为 `xieyuhua`）。
> 若你改用其他值，请自行替换下文中的端口与密钥。

完整参考（全部配置项、管理 API、流程图）见 [README](../README.md)。

---

## 0. 这是什么

apitoken 是一个 **OpenAI 兼容的大模型网关**：把 DeepSeek、商汤、腾讯 WorkBuddy 等各平台的
API Key 集中管理，对外只暴露一个地址 + 一把网关密钥。客户端只认网关，不关心背后走的是哪家。

```
客户端 ──> 网关 (http://127.0.0.1:18125/v1) ──> DeepSeek / 商汤 / 腾讯 / ...
              │
              └── 按优先级+权重分流、失败自动切换、统一记账与日志
```

## 1. 准备与启动

需要 [Go 1.24+](https://go.dev/dl/)。

```bash
# 构建（Windows 生成 apitoken.exe）
go build -o apitoken ./cmd/gateway

# 启动
./apitoken -config config.yaml
```

看到监听日志即启动成功。打开浏览器访问：

| 地址 | 用途 |
| --- | --- |
| http://127.0.0.1:18125/ | Web 控制台（渠道、路由、看板） |
| http://127.0.0.1:18125/logs | 调用日志 |
| http://127.0.0.1:18125/chat | 对话测试页 |
| http://127.0.0.1:18125/settings | 设置（密钥、路由、日志、超时） |
| http://127.0.0.1:18125/v1 | OpenAI 兼容接口 |

也可以直接用 Makefile：`make build`、`make run`。

## 2. 安全第一步：改密钥

`config.yaml` 里两把钥匙，**生产环境务必修改**：

```yaml
security:
  client_keys:          # 客户端调用网关时用的密钥
    - xieyuhua
  admin_token: xieyuhua # 登录 Web 控制台 / 调管理接口用的令牌
```

- `client_keys`：给客户端（curl、SDK、Cline 等）用，配在 `Authorization: Bearer` 里。
- `admin_token`：登录控制台和管理 API，配在请求头 `X-Admin-Token` 里。

改完后重启生效；也可以在「设置」页在线修改（立即生效并写回配置）。

---

## 3. 添加第一个渠道

1. 打开 http://127.0.0.1:18125/ ，右上角填入 `admin_token`（`xieyuhua`）保存。
2. 点「添加渠道」，填三样东西：
   - **Base URL**：填到 `/v1` 这一层，例如 `https://api.deepseek.com/v1`（输入框有常用平台提示）。
   - **API Key**：该平台的 Key。
   - **支持的模型**：该渠道能用的模型名（逗号分隔；留空 = 放通所有模型名）。
3. 点「测试连通性」验证（会真实发一条 `ping`）；或点「拉取模型」从上游拉取列表后勾选写入。
4. 保存。

常用平台 Base URL 速查（完整列表见 README 第 2 节）：

| 平台 | Base URL |
| --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` |
| 商汤日日新 | `https://token.sensenova.cn/v1` |
| 腾讯云 WorkBuddy | `https://api.copilot.tencent.com/api/v1` |
| OpenAI | `https://api.openai.com/v1` |

## 4. 第一次调用

### curl

```bash
curl http://127.0.0.1:18125/v1/chat/completions \
  -H "Authorization: Bearer xieyuhua" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"你好"}]}'
```

### Python（OpenAI SDK）

```python
from openai import OpenAI

client = OpenAI(api_key="xieyuhua", base_url="http://127.0.0.1:18125/v1")

resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)
```

### 第三方客户端（Cline / Chatbox / NextChat 等）

- Base URL 填 `http://127.0.0.1:18125/v1`
- API Key 填 `xieyuhua`
- 模型名填你在渠道里声明的模型名（或「拉取模型」得到的名字）

> 想要 Anthropic 协议的客户端（Claude Code 等）？网关同时提供
> `http://127.0.0.1:18125/v1/messages` 入口，同样用网关密钥，详见 README 9.6。

## 5. 快速验证是否可用

打开 **对话测试页** http://127.0.0.1:18125/chat ：

1. 填网关地址与密钥（历史连接下拉会记住你连过的地址）。
2. 点「拉取模型」，下拉里选一个模型。
3. 发一句话，能正常回复即说明全链路打通。

## 6. 常用场景

### 6.1 一个模型多个账号（负载均衡 / 故障转移）

给同一个模型加多个渠道，用两个字段控制：

- **优先级（priority）**：越小越优先；
- **权重（weight）**：同优先级内按权重分流。

默认策略 `priority_round_robin`：先按优先级分组，组内按权重轮询。
想严格「主备不轮询」：策略改成 `failover`（见「设置 → 路由策略」或 README 第 5 节）。

### 6.2 对外模型名与上游不一致（模型映射）

某些客户端写死模型名（如 `gpt-4o`），但你的渠道上是别的名字。用**显式路由**做映射：

```yaml
routes:
  - model: "gpt-4o"            # 客户端用的名字
    channels: ["deepseek-1"]   # 走哪个渠道（可多个，顺序即切换顺序）
    model_map:
      deepseek-1: "deepseek-chat"   # 该渠道上的真实模型名
```

也可在控制台「路由」页用下拉点选完成，无需手写 YAML。

### 6.3 失败自动切换

上游返回 429/5xx 或超时，网关自动切换下一个渠道（受 `routing.max_attempts` 限制）。
失败的渠道会进入**冷却**（默认 60s），冷却期内不再尝试，成功即恢复。

## 7. 查看日志与用量

- **看板**：http://127.0.0.1:18125/ （命中条数、成功率、Token 用量、延迟）。
- **调用日志**：http://127.0.0.1:18125/logs （每次请求的模型、渠道、状态、来源 IP、User-Agent、耗时、故障转移链路；支持筛选与 CSV/JSON 导出）。
- 点日志里的「详情」可看一次请求的**完整调用链路**（每次尝试的渠道、端点、错误、请求/回复摘要）。

日志默认异步落盘为 JSONL（`data/logs/`），重启不丢；条数与保留策略见 README 10.4。

## 8. 常见问题速查

| 现象 | 排查 |
| --- | --- |
| 返回 `404 Route Not Found` | 网络出口/代理问题，先「测试」渠道；必要时在该渠道配置「上游代理」（代理地址或 `none` 强制直连） |
| 上游 `401 / Forbidden` | Key 无效或填错平台；各平台 Key 不通用 |
| 模型名找不到（404） | 渠道「支持的模型」里没写这个名；留空 = 放通全部（慎用） |
| 点「编辑」路由却多出一条 | 路由按对外模型名 upsert：**改名=新增**，改名会弹窗确认 |
| 密钥忘了怎么看 | 「设置」页可查看（脱敏）；配置在 `config.yaml` / `data/gateway.json` |

更多问题见 README 第 8 节。
